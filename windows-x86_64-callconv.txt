Microsoft Windows x86-64 Calling Convention.
Соглашение о вызовах Microsoft Windows x86-64.

Данное соглашение о вызовах вдохновлено "fastcall".

Теневое пространство / Shadow Space.
Для вызова функции обязательно нужно зарезервировать теневое пространство в стеке. Размер теневого
    пространства должен быть кратен 16 и минимально быть 32 байта, то есть равен размеру первых
    четырёх аргументов (32 байта — размер 4 аргументов: 4 * 8 = 32).
Примеры:
    sub rsp, 32 ; NASM
    subq $32, %rsp # GAS

Регистры.
Аргументы для передачи в функции передаются в регистрах:
    1. RCX (целочисленный аргумент) / XMM0 (аргумент с плавающей точкой).
    2. RDX (целочисленный аргумент) / XMM1 (аргумент с плавающей точкой).
    3. R8 (целочисленный аргумент) / XMM2 (аргумент с плавающей точкой).
    4. R9 (целочисленный аргумент) / XMM3 (аргумент с плавающей точкой).
    Остальные аргументы передаются в стеке на месте 5 регистра (с учётом теневого пространства).
Ну и да, аргументы с плавающей точкой передаются в XMMn регистрах, так как Windows уже давно
    в минимальных системных требованиях требует процессор с поддержкой SSE2.
Для возврата значения из функции используется регистр RAX.
Также существуют следующие типы регистров:
    1. Volatile / Caller-saved — регистры, которые можно затирать любой вызываемой функции, коими являются:
        1. RAX.
        2. RCX.
        3. RDX.
        4. R8.
        5. R9.
        6. R10.
        7. R11.
        8. XMM0.
        9. XMM1.
        10. XMM2.
        11. XMM3.
        12. XMM4.
        13. XMM5.
    2. Nonvolatile / Callee-saved — регистры, которые обязательно должна сохранять (например, в стек)
        вызываемая функция, коими являются:
        1. RBX.
        2. RBP.
        3. RDI.
        4. RSI.
        5. RSP.
        6. R12.
        7. R13.
        8. R14.
        9. R15.
        10. XMM6.
        11. XMM7.
        12. XMM8.
        13. XMM9.
        14. XMM10.
        15. XMM11.
        16. XMM12.
        17. XMM13.
        18. XMM14.
        19. XMM15.

Стек и его очистка.
Перед любым вызовом функций (call), стек должен быть выровнен по 16 байт.
За очистку стека от аргументов, переданных через стек ответственна вызывающая сторона.
